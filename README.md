# EVA — Бизнес-ассистент

**Бот и мини-приложение в MAX, которые закрывают отпуск сотрудника от заявки до закрытой смены — без кадровика.**

Сотрудник подаёт заявку на отпуск прямо в MAX → EVA мгновенно проверяет её по правилам Трудового кодекса и объясняет решение → руководитель соглашается одним нажатием в чате → формируются документы → а освободившаяся смена в ту же секунду предлагается тем коллегам, кто может выйти.

## Что умеет EVA сейчас

### 📋 Заявка на отпуск и движок правил

Сотрудник выбирает даты в мини-аппе и сразу видит вердикт — зелёный / жёлтый / красный, с объяснением и ссылкой на статью закона. Проверка идёт **до** подачи заявки (`POST /leave-requests/preview`), решение приходит мгновенно, а не через несколько дней.

Движок правил (`api/app/rules`) считает результат по 11 проверкам:

| Проверка | Что делает |
|---|---|
| Остаток дней | Накопление 2,33 дня за отработанный месяц, остаток на любую дату |
| Минимальная часть 14 дней | Хотя бы одна часть отпуска не короче 14 календарных дней |
| Срок извещения | Не позднее чем за 2 недели до начала |
| Праздничные дни | Пересчёт — нерабочие праздники не входят в число дней отпуска |
| Срок выплаты | Крайняя дата — не позднее 3 дней до начала |
| Два года подряд | Запрет непредоставления отпуска два года подряд |
| Льготные категории | Предупреждение для многодетных, несовершеннолетних, доноров и др. — не блокирует |
| Пересечение по смене | Конфликт с уже одобренным отпуском коллеги на той же точке/должности |
| График Т-7 | Соответствие уже утверждённому графику отпусков |
| Первые 6 месяцев | Особые условия для новых сотрудников |
| Расширенная база | Увеличенная длительность для отдельных категорий |

### ✅ Согласование и документы

- Руководителю в чат бота приходит карточка с готовым решением и кнопками «Согласовать» / «Отклонить».
- Согласование подтверждается биометрией MAX (`BiometricManager`) в мини-аппе — на iOS/Android. Если биометрия недоступна (веб-клиент, десктоп — так задокументировано в MAX Bridge), используется ручное подтверждение.
- При согласовании автоматически формируются 3 PDF-документа (заявление, приказ Т-6, уведомление) с кириллицей и sha256-хешем целостности, списывается остаток дней отпуска.
- Документ можно посмотреть прямо в приложении, скачать или отправить ссылку в чат — через реальные методы MAX Bridge (`downloadFile`, `shareMaxContent`).
- Отзыв уже согласованного отпуска — с возвратом баланса.

### 🔄 Подмены (матчинг смен)

Согласование отпуска автоматически открывает смену на этот период. Дальше:

- Руководитель открывает список открытых смен и подбор кандидатов (`score_candidates` в `api/app/matching.py`).
- В подбор попадают сотрудники той же точки, с той же должностью, нужными допусками, свободным окном в своей доступности на этот день/час и без конфликтов по отпуску или уже принятым сменам.
- Кандидаты ранжируются по близости к точке, числу подтверждённых смен и неявкам — с человеко-понятными причинами для каждого.
- Руководитель свайпает карточки кандидатов, предложение уходит кандидату в чат с кнопкой «Выйду» прямо в сообщении или через мини-апп.
- Отказ возвращает смену в пул и уведомляет всех руководителей точки — можно предложить следующему.

Сотрудники сами включают доступность для подработки по дням недели и часам на экране «Подработка» — это и есть пул, из которого матчинг берёт кандидатов.

### 📅 График отпусков на год (Т-7)

Руководитель командой `/collect_schedule <год>` разом приглашает всех сотрудников указать желаемые даты на будущий год. Ответы собираются в мини-аппе, `/approve_schedule <год>` утверждает график и подсвечивает пересечения дат.

### 🧾 Аудит и проверка

- Каждое действие (подача, согласование, отклонение, подпись, предложение смены, принятие/отказ) пишется в журнал аудита с хеш-цепочкой (`prev_hash`) — запись задним числом не подделать незаметно.
- Журнал с фильтрами по сотруднику/заявке/периоду доступен руководителю, бухгалтеру и админу.
- Кнопка «Собрать папку к проверке» формирует ZIP (журнал в CSV, все PDF, сводка) за период — отдаётся по подписанной HTTPS-ссылке.

### ⏰ Напоминания

Фоновый планировщик (интервал задаётся `REMINDER_SWEEP_INTERVAL_SECONDS`) сам присылает: сотруднику — напоминание о сроке извещения, бухгалтеру — о сроке выплаты отпускных, руководителю — эскалацию, если заявка зависла ближе к дедлайну, и приветствие «С возвращением» в день выхода из отпуска.

### 👥 Онбординг и роли

- Компания создаётся с нуля прямо из мини-аппа (`POST /companies`) — без отдельного сайта регистрации.
- Сотрудник подключается по одноразовой ссылке от `/add_employee` или QR-коду в мини-аппе.
- Роли (`employee`, `manager`, `accountant`, `admin`) не взаимоисключающие: у одного человека может быть несколько (например, владелец компании — он же руководитель точки). Каждый созданный сотрудник автоматически получает базовую роль `employee` — руководитель, бухгалтер и админ тоже могут поставить себе отпуск.

## Команды бота

| Команда | Кто использует | Что делает |
|---|---|---|
| `/start` | Все | Открывает EVA, показывает список команд и кнопку мини-аппа |
| `/add_employee Фамилия Имя; Должность; роль` | Руководитель, админ | Создаёт сотрудника и выдаёт одноразовую ссылку-приглашение. Роль необязательна (по умолчанию `employee`) |
| `/collect_schedule <год>` | Руководитель | Рассылает всем сотрудникам приглашение указать даты отпуска на год |
| `/approve_schedule <год>` | Руководитель | Утверждает собранный график, подсвечивает пересечения дат |

Тот же список зарегистрирован в нативном меню команд MAX (`bot.set_commands`) — доступен через «/» в чате с ботом.

## Роли

| Роль | Доступ |
|---|---|
| `employee` | Подать заявку на отпуск, посмотреть свои заявки и документы, календарь команды, доступность для подработки |
| `manager` | Входящие заявки, согласование/отклонение, команда, подбор подмен, график Т-7 |
| `accountant` | Реестр документов, сроки выплат, журнал аудита |
| `admin` | Сотрудники и их роли, настройки, справочник правил |

Роли комбинируются — сотрудник с несколькими ролями видит переключатель между разделами.

## Ограничения текущей версии

Чтобы не создавать ложных ожиданий:

- **Нет расчёта сумм** отпускных и зарплатных данных — только контроль срока выплаты.
- **Нет интеграции с 1С** — сотрудники, остатки дней и справочник должностей загружаются как тестовые данные при первом старте (`api/app/seed.py`), помечены в интерфейсе.
- **Подбор подмен работает внутри одной точки/компании** — межкомпанийный обмен не реализован.
- **Биометрия работает только в мобильном MAX** (iOS/Android) — так задокументировано в MAX Bridge; в веб-версии и на десктопе всегда используется ручное подтверждение.
- **Управление списком точек** — в настройках админа показывается их число, отдельного экрана создания/редактирования пока нет (создание точки есть на бэкенде: `POST /locations`).

## Архитектура

```
MAX (мессенджер)
├── Bot (aiohttp + maxapi) ── уведомления, карточка согласования,
│                             команды руководителя, приём предложений смен
└── Mini App (React + MAX UI + MAX Bridge) ── заявки, документы,
                              подбор подмен, доступность, настройки
                                      │
                                      ▼
                             Backend API (FastAPI)
                             ├── Rules Engine — правила как данные
                             ├── Matching — подбор кандидатов на смену
                             ├── Генерация PDF (fpdf2 + DejaVu)
                             ├── Аудит с хеш-цепочкой
                             └── Планировщик напоминаний
                                      │
                                 PostgreSQL

nginx — реверс-прокси + отдача мини-аппа + TLS (Let's Encrypt/certbot)
```

Бот и мини-апп аутентифицируются перед API по-разному: мини-апп — подписанным `X-Max-Init-Data` (HMAC, проверяется на бэкенде), бот — отдельным общим секретом (`X-Internal-Secret`), независимо от режима проверки подписи мини-аппа.

## Запуск

```bash
cp .env.example .env   # заполнить реальными токенами и секретами
docker compose up -d --build
```

Поднимутся `postgres`, `api`, `bot`, `nginx` (+ `certbot` для продления сертификата). Для первого выпуска TLS-сертификата на голом IP — `scripts/init-letsencrypt.sh`.

## Структура репозитория

```
api/      — backend (FastAPI): правила, документы, матчинг, аудит
bot/      — бот (aiohttp + maxapi): команды, уведомления, карточки в чате
frontend/ — мини-апп (React + Vite + MAX UI)
nginx/    — конфиг и Dockerfile реверс-прокси
scripts/  — вспомогательные скрипты деплоя
```
