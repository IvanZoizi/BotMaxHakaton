# СМЕНА — фронтенд мини-аппа MAX

React + TypeScript + Vite + [`@maxhub/max-ui`](https://dev.max.ru/ui) + MAX Bridge. Реализует все экраны для 4 ролей (Сотрудник, Руководитель, Бухгалтер, Админ) по дизайну в Figma и API-контракту `openapi.yaml`, с полностью рабочим мок-API вместо реального бэкенда.

## Быстрый старт

```bash
npm install
npm run dev
```

Откроется на `http://localhost:5173`. Внизу экрана — плавающая DEV-панель для переключения роли, статуса подключения (`isLinked`/`NOT_LINKED`) и темы (`light`/`dark`) — в реальном MAX это определяется на сервере/системой, здесь эмулируется вручную для демонстрации всех ролей без бэкенда.

```bash
npm run build    # tsc -b && vite build → dist/
npm run preview  # локальный просмотр production-сборки
npm run lint      # oxlint
```

## Стек и интеграция с MAX

- **`@maxhub/max-ui`** — компоненты дизайн-системы MAX (`Switch` и др.), обёрнуты в `<MaxUI colorScheme={theme}>` в `App.tsx`.
- **MAX Bridge** (`src/bridge/maxBridge.ts`) — обёртка над `window.WebApp` (скрипт `https://st.max.ru/js/max-web-app.js`, подключён в `index.html`). Все вызовы (`biometric.authenticate`, `shareMaxContent`, `downloadFile`, `openCodeReader`, `requestContact`) обёрнуты в `safeCall`, который ловит ошибки и подставляет разумный fallback — это не паранойя: реальный скрипт MAX Bridge подключается и вне MAX-клиента (например, в обычном браузере при разработке) и падает при вызовах, для которых не был предварительно вызван `.init()` или для которых недоступно железо. Без этой обёртки экран подписания документа крашился при обычном браузерном превью.
- Вне реального MAX-клиента (`maxBridge.isNative() === false`) всё работает на моках: биометрия имитируется, `downloadFile` кликает по `<a>`, `openCodeReader`/`requestContact` возвращают тестовые данные.

## Мок-API вместо бэкенда

Настоящего бэкенда нет — вся логика в `src/api/`:

| Файл | Назначение |
|---|---|
| `types.ts` | TypeScript-типы 1:1 с `components.schemas` из `openapi.yaml` (39 схем, 16 путей) |
| `fixtures.ts` | Сид-данные: сотрудники, заявки, документы, правила, смены, аудит-лог |
| `rulesEngine.ts` | Настоящий движок правил (не заглушка): остаток дней, извещение за 14 дней, минимальная часть отпуска, праздники, пересечение по команде — воспроизводит все 3 сценария демо-скрипта из корневого README (зелёный/жёлтый/красный вердикт) |
| `mockApi.ts` | Функции на каждый из 16 эндпоинтов контракта + отдельно помеченные GAP-заглушки (см. ниже), с задержкой (`network.ts`) и теми же кодами ошибок, что в контракте (`NOT_LINKED`, `FORBIDDEN`, `VALIDATION_ERROR`, `RULE_VIOLATION`, `ALREADY_RESOLVED`, `CONFLICT`) |
| `errors.ts` | Класс `ApiError` + фабрики ошибок |

**Важно:** состояние мока живёт только в памяти вкладки. Обновление страницы (`F5`, полная навигация) сбрасывает все изменения (поданные заявки, подписи и т.д.) к исходным фикстурам — это ограничение мок-подхода без бэкенда/`localStorage`, а не баг.

### GAP-заглушки

API-контракт (`СМЕНА — API-контракт и OpenAPI.md`, раздел 7) сам фиксирует 6 мест, где Figma требует экран, а архитектурный MD не даёт эндпоинта. Они реализованы как моки, явно помеченные в коде комментарием `GAP-0X` и (где это видно пользователю) плашкой ⚠ на экране:

- **GAP-01** — подписание документа (`signDocument` в `mockApi.ts`)
- **GAP-02** — вид документа «Уведомление об отпуске» (добавлен как `'notice'` в `DocumentKind`, см. комментарий в `types.ts`)
- **GAP-03** — реестр всех документов компании (`listAllDocuments`/`listAllDocumentsWithOwner`)
- **GAP-04** — сроки выплат и отметка о выплате (`listPaymentDeadlines`, `markPaid`) — суммы отпускных **фиктивны** (условная ставка ₽/день), в контракте таких данных нет
- **GAP-05** — отклонение предложения смены (`declineShiftOffer`)
- **GAP-06** — весь Admin-контур (создание компании, сотрудники, настройки) — сделан **read-only**, без CRUD (по договорённости — коллега подтвердил, что для демо достаточно списка)

### Другие мок-only расширения (не часть контракта)

Кроме GAP'ов, есть точки, где дизайн в Figma показывает данные, которых явно нет в схемах контракта (например, `Employee` намеренно не содержит остаток дней — «чужой остаток никто не видит», но экраны «Входящие»/«Команда»/«Сотрудники» его всё равно показывают). В каждом таком месте в коде оставлен комментарий с объяснением конфликта:

- `EMPLOYEE_BALANCE_DAYS`, `SHIFT_LEAVE_REQUEST` в `fixtures.ts`
- `getRuleExplanation` (`lib/ruleExplanations.ts`) — полный текст нормы для BottomSheet/Rule, которого нет в схеме `Rule`/`CheckResult`

## Структура

```
src/
  api/          мок-бэкенд (см. выше)
  bridge/       обёртка над MAX Bridge
  components/   переиспользуемые UI-компоненты (дизайн-система из Figma, страница «02 — Components»)
  context/      authStore (роль/isLinked), themeStore — вне React, чтобы читаться из mockApi без хуков
  lib/          хелперы: даты, useAsync (loading/error/retry), форматирование
  pages/
    employee/   Connect, Home, NewRequest, MyRequest, MyDocuments, DocumentDetail,
                Signing, TeamCalendar, Availability, ShiftOfferScreen
    manager/    Inbox, Approval, Team, Substitution
    accountant/ Registry, Deadlines, ReviewQueue, AuditJournal
    admin/      CompanyConnect (мастер из 3 шагов), Employees, Settings, SettingsRules
  routes/       AppRoutes (react-router), RoleGate (редирект по роли/isLinked)
  styles/       tokens.css (цвета/типографика/spacing из Figma «01 — Foundations»), global.css
```

Каждая страница — самостоятельный маршрут; общие паттерны (шапка, нижняя навигация, скелетон/пустое/ошибка/forbidden) вынесены в `components/`.

## Тема

Дизайн в Figma — **только светлый** (тёмные значения на странице Foundations — это задокументированные токены про запас, не отдельные тёмные мокапы экранов). Поэтому светлая тема — единственная автоматическая по умолчанию, **не** зависит от `prefers-color-scheme` системы. Переключить на тёмную можно только вручную через DEV-панель (`themeStore.ts`).

## Известные ограничения

- Нет персистентности мок-данных между полными перезагрузками страницы (см. выше)
- Часть экранов Manager/Accountant/Admin (состав нижней навигации, некоторые подписи) собрана по смыслу там, где в общем Figma-файле нет готового артефакта — такие места помечены комментариями в коде
- Реальных файлов PDF нет — `pdfUrl` в документах указывает на несуществующие `example.org` ссылки, страницы предпросмотра показывают заглушку «PDF preview»
